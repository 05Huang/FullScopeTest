# API v1 到 v2 迁移指南

> 本文档描述 API v1 到 v2 的迁移策略和时间表

---

## 📋 概述

项目正在逐步从 API v1 迁移到 v2。v2 API 提供了更规范的接口设计和更好的类型支持。

## 🗓️ 迁移时间表

| 阶段 | 时间 | 说明 |
|------|------|------|
| 阶段 1 | 已完成 | v2 API 开发完成 |
| 阶段 2 | 进行中 | v1 API 标记为 deprecated |
| 阶段 3 | 2026-Q3 | 前端迁移到 v2 API |
| 阶段 4 | 2026-Q4 | 移除 v1 API |

## 🔄 主要变更

### 1. 响应格式

v2 API 统一使用以下响应格式：

```json
{
  "code": 200,
  "data": {},
  "message": "success",
  "timestamp": "2026-06-02T00:00:00Z"
}
```

### 2. 分页格式

```json
{
  "code": 200,
  "data": {
    "items": [],
    "pagination": {
      "total": 100,
      "page": 1,
      "per_page": 20,
      "pages": 5
    }
  }
}
```

### 3. 错误响应

```json
{
  "code": 400,
  "data": null,
  "message": "参数错误",
  "errors": {
    "field": "错误详情"
  }
}
```

## 🚀 迁移步骤

### 前端迁移

1. 更新  中的 baseURL
2. 更新各 Service 文件中的 API 端点
3. 处理响应格式变更
4. 测试所有功能

### 后端迁移

1. 确保 v2 API 功能完整
2. 在 v1 API 响应中添加 deprecation 警告
3. 监控 v1 API 使用情况
4. 逐步移除 v1 API

## ⚠️ 注意事项

1. v1 和 v2 API 将在过渡期内共存
2. 新功能将只在 v2 API 中提供
3. v1 API 将在 2026-Q4 完全移除
